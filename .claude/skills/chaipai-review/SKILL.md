# 拆拍台评审

这份 skill 只是入口。**流程、评分标准、归因规则、各角色的指示，全部以下面这些文件为准，照做，不要凭记忆：**

- 总则与一轮怎么跑：`编排/评审/README.md`
- 评分标准（冻结，迭代期间不许改）：`编排/评审/评分标准.md`
- 归因规则：`编排/评审/归因规则.md`
- 角色指示（派生子 agent 时让它自己去读，占位符由你在提示里给值）：`编排/评审/角色/`
- 测试故事：`编排/评审/故事/`（03 是留出的，不参与迭代）
- 每轮存档：`编排/评审/轮次/<故事>-第N轮/`

## 调度要点（README 里有，这里只列最容易错的）

1. 每轮换新端口起服务：`node 编排/评审/服务.cjs <端口> <轮次目录>`——新端口＝干净的页面存储。
2. A 每轮都是全新的子 agent；追问时用 SendMessage 接回同一个。A 只准操作浏览器页面，不准读 `编排/` 下除它的角色文件和故事文件之外的任何东西。
3. A 做完后，由你在 A 的标签页里执行 `fetch('/__save',{method:'POST',body:JSON.stringify(doc)})` 把数据落盘，再跑 `node 编排/评审/导出.cjs <轮次目录>`。
4. B1、B2 同时派，互不通气；都跑完再派 B 判定。
5. 不通过：按归因规则逐条归因，**默认是工具的问题**；只修阻塞问题；修复不许让字段预算和操作步数上涨，涨了要在 `修复.md` 写理由。
6. 每个故事最多 4 轮；标准冻结；留出的故事最后只验一次。
7. 每个大版本跑完，把最新一份 `A-卡顿日志.md` 指给制作人翻一眼——这个流程测不出他用起来累不累。

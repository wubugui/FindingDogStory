## 官方用法与本机 Hub 的实际边界

- 2026-09-25 复核 Hub 连通性时，默认 PowerShell `Invoke-WebRequest` 返回代理的 502；同机 `curl.exe --noproxy "*" http://denghong01:8765/health` 直连得到 HTTP 200、`service=inference-hub`，`/guide.md` 和 `/capabilities.json` 也可直连。后续请求必须按项目规则使用主机名并绕开代理，不能把代理 502 误判成生成服务宕机。

- [Qwen-Image-2.1 官方仓库](https://github.com/QwenLM/Qwen-Image-2.1)支持单图编辑和至多十张参考图；官方示例默认 40 步。40 步是默认值，并不能单独保证构图或比例正确。
- [官方编辑提示词规则](https://github.com/QwenLM/Qwen-Image-2.1/blob/main/prompt_rewrite/prompts/system_prompt_edit.txt)要求多图时明确 `<image1>`、`<image2>` 的角色，指定哪张是保留构图的画布；局部编辑只描述要改变的内容，其余用一条保留要求概括，避免把“保留细节”写成大段重新生成指令。
- 同一官方规则将**人物身份**列为最难稳定保持的属性，建议直接指向参考图而非只用文字描写五官和衣服。AX04 已用高清 GameDraft 角色 ref 直接输入验证；只有画面审核通过才能恢复为可用电影图。
- 官方编辑提示词规则还把输出比例单独交给 `wh_ratio` / `ratio_follow`，要求编辑描述本身不夹带分辨率，并尽量用肯定句说清改动与保持项。本机 Hub 的对应画幅控制是 `qwen_canvas`、`width`、`height`、`reference_resolution`；后续请求把像素尺寸放在参数中，提示词专注动作和局部位置。此前候选提示词混写过尺寸，不应照抄为模板。
- Hub 当前 `/capabilities.json` 报告 `Qwen-Image-2.1`、`local ComfyUI int8_convrot`、最多 10 张参考图；没有安装官方 PE-T2I/PE-I2I 提示词改写器。Hub 的 `qwen_canvas="first_reference"` 按 `reference_resolution` 重算画布，`explicit` 按 `width/height` 输出。不能把参考图画布当作绝对的像素锁。
- Hub 无单独的“人物像素高度锁”或“相机锁”参数。多参考图是语义条件，不是把角色自动按游戏世界坐标放置的渲染器。

## 后续逐张门槛

1. 先确认每张输入的本地绝对路径、SHA256 和 Hub file ID；若原始来源是 GPT/Qwen 生成文件，直接禁止入本轮请求。`origin="uploaded"` 只说明传输方式，不能证明内容是游戏原素材。
2. 模拟实机优先以**一张同机位原实机截图**为主画布，用 `explicit` 输出相同宽高，只修改目标小区域。确需第二张参考时明确各图职责，不喂带黑底的大幅道具板去要求“整幅实景”。
3. 概念图单独从游戏原场景与角色 ref 生成电影机位；参考图是身份和建筑依据，不要求“像素级照抄”。
4. 下载后核对 Hub SHA256、实际宽高、人物头脚像素区间、脚底接地、地标、镜头、叠图边缘和剧情动作。先验收一张再扩批；不通过的候选与请求保留，但不送 H3。
5. 出现矩形边界时先查真实运行时：[码头水下小游戏](demo_h3_firstframes/runtime_capture/码头水下_dock_crate_tutorial_原生小游戏_1024x768.png)、[梦里屋盖脸纸](demo_h3_firstframes/runtime_capture/梦_里屋_盖脸纸_原生演出_1024x768.png)和[河边递纸](demo_h3_firstframes/runtime_capture/V14_河边递纸_原生伸手演出_1024x768.png)确有内嵌画框；旧 F02 黑底道具板与旧 AX03 人工布局图则是错误输入/提示词引入的叠图。判定依据是**与对应原生事件同机位、同时间点的实机画面比对**，不能只按“有黑边”或“没黑边”打分。

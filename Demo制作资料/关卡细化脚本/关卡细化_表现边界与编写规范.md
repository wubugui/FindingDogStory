# 《寻狗记》关卡细化 · 表现边界与编写规范

> **文档用途**：约束《游戏总纲》向可落地关卡脚本细化时的表现尺度，防止写出当前游戏形式无法承载、或需要大量未声明新资产的演出。
>
> **适用范围**：Demo 主线、可选支线、开放街区、对话事件、过场、小游戏及后续正式版关卡。
>
> **工程核查基准**：2026.07.15，`wubugui/GameDraft` 正式 Web 运行时；Vite + TypeScript + PixiJS 8。本地核查分支 `feature/ground-fit-depth-editor`，提交 `a2f5b9c`。工程能力或素材变化后，应重新核查本文件。

---

## 零、工程权威口径

本项目当前正式表现引擎是 **Web／TypeScript／PixiJS**。

判断关卡能否落地时，按以下顺序核查：

1. `GameDraft/src/`：正式 Web 运行时、Pixi 渲染、UI、系统与动作能力。
2. `GameDraft/public/assets/`：正式场景、对话、任务、演出、动画、图片和声音数据。
3. 正式 TypeScript／Pixi 运行截图、浏览器运行态和内容编辑器实际可配置范围。
4. `GameDraft/godot_port/` 仅是跨引擎迁移与对齐实验，不作为当前游戏形式、表现上限或生产能力的权威来源。

PixiJS 作为 2D Web 渲染引擎，本身可以通过新代码继续增加粒子、Shader、特殊合成、专属 UI 和小游戏。本文限制的是 **当前正式运行时已经稳定暴露给内容生产的能力**，不是宣称 PixiJS 理论上永远做不到某种效果。

## 一、游戏当前的真实表现形式

《寻狗记》当前是 **运行在浏览器中的、1024×768 逻辑视口、2D 斜俯视、手绘场景驱动的民俗恐怖冒险游戏**。

玩家主要看到和操作的是：

- 一张高精度手绘场景背景。
- 在背景中独立移动的关二狗和少量关键 NPC。
- 场景中的调查点、出入口、NPC、物品和遭遇触发点。
- 对话框、选项、人物小半身立绘、气泡、提示和状态 UI。
- 镜头平移、缩放、淡入淡出、白闪、遮罩和环境滤镜。
- 全屏静态插画、缓慢推拉、分层视差、字幕、配音与音效构成的过场。
- 水下拖拽、长按沉默、扎纸、糖画等独立小游戏或具身操作。
- 基于深度图的角色遮挡、脚底接触关系和前后景穿插。
- 角色环境色融合、AO、真实或平面投影阴影及位置变化的光照环境。
- 作用于整个世界画面的色彩滤镜，以及覆盖图之间的渐变混合。
- 键鼠、触屏控制和随浏览器窗口缩放的 Web 画布。

它不是以下形式：

- 不是可以自由旋转镜头、切换摄影角度的 3D 游戏。
- 不是所有背景人物都能独立行动的实时群戏系统。
- 不是依靠连续面部表演和复杂肢体接触讲戏的电影化游戏。
- 不是实时物理、自由战斗或大规模追逐驱动的动作游戏。

因此，关卡脚本必须优先利用 **空间、声音、对话、停顿、少量关键动作、环境变化和玩家亲手操作** 表现剧情。

## 二、表现力的三档边界

### A 档：现有能力与素材可直接落地

这类内容可以放心写入关卡正式流程：

- 关二狗在场景内行走、奔跑、停下、接近、绕开和离开。
- 关键 NPC 站立、行走、巡逻、转向、靠近或离场。
- 玩家调查物件、拾取物品、进入出口、与 NPC 对话、触发遭遇。
- 对话选项、条件分支、金钱与物品变化、任务推进、NPC 后续态度变化。
- 对话立绘、人物表情、气泡、简短情绪符号和背景压暗。
- 镜头平移、缩放、淡黑、淡入、白闪、电影黑边和字幕。
- 播放已有环境声、脚步、敲击、风雨、尸响等音效。
- 显示已有覆盖图、特写物件、气味提示、三把火和死亡系绳反馈。
- 使用现有背尸动作：抬尸、背负、沉重行走、踉跄、调整肩膀、放下、倒地。
- 使用现有水下、长按压力、扎纸、糖画玩法。

### B 档：现有运行时支持，但必须声明新增资产

这类内容不是不能写，但必须在脚本中明确标注“新增资产”，不能假装现成可用：

- 关二狗或 NPC 的专属动作，如偷鸡、踢狗、挨咬、被推、偷橘子、贴墙缩肩。
- 两个角色发生明确肢体接触，如搡肩、拉扯、背起、拖拽、扭打。
- 独立的猫、狗、鸡、袍哥、追兵、轿夫等角色及其动作。
- 门、窗、碗、饼、扁担、棺材等物件发生可见状态变化。
- 某个背景人物从静态背景中“活起来”。
- 新的全屏插画、局部特写、分层视差镜头或循环动画覆盖层。
- 新的场景背景、街区分区、昼夜版本或破坏后的场景版本。
- 新的环境滤镜、覆盖图、光照配置和场景氛围版本。

写入 B 档内容时，必须同时说明：

1. 需要什么角色、物件或画面资产。
2. 需要几个动作状态。
3. 是否可以用插画、音效或对话替代实时表演。
4. 如果资产被砍，剧情信息如何保留。

### C 档：Pixi 技术上可扩展，但当前没有现成内容原语

以下内容不是 PixiJS 理论上做不到，而是当前正式运行时没有可直接配置的稳定原语。若没有单独立项，不应写成必然会实时发生的正式演出：

- 大量群众同时转头、起身、挪凳、捂鼻、端碗、交头接耳。
- 三人以上长时间、精确同步的连续肢体表演。
- 依靠手指、眼神、嘴角、握力等微表情才能读懂的关键剧情。
- 任意改变俯仰角、环绕人物、穿越空间的 3D 摄影机运动。
- 可破坏环境、真实玻璃碎裂、复杂布料、液体或绳索物理。
- 无预制动作的实时打斗、多人追逐和自由擒抱。
- 要求玩家从很小的世界角色脸部辨认复杂情绪。
- 在一个并行演出块内部精确安排“先等几秒，再依次做多个动作”的复杂编舞。
- 全新的粒子系统、骨骼动画系统、布料或刚体物理。
- 当前四类之外的新小游戏框架或新的连续操作系统。
- 需要新增动作类型、条件类型、演出步骤或独立运行系统的玩法。

C 档内容若确有必要，必须先写成“能力升级需求”，单独说明玩家价值、复用范围、最低实现和砍减方案；不能在普通关卡脚本里把它悄悄当成已有功能。

确实需要这些效果时，应改用以下方式之一：

- 把关键瞬间做成全屏插画或局部特写。
- 用一到两个独立角色代表整群人的反应。
- 用环境声骤停、窃窃私语、碗底磕桌、椅脚拖地等声音表现群体变化。
- 用对话立绘和台词承担细微情绪。
- 把连续复杂动作拆成几个清楚的镜头和状态跳变。

## 三、各类内容最适合的表现载体

| 剧情需求 | 首选载体 | 不应默认使用 |
|---|---|---|
| 人物关系、嘴硬、撒谎、试探 | 图对话、选项、立绘、停顿 | 世界角色细微表情 |
| 群体排斥、气氛变冷 | 环境声变化、两名代表 NPC、空间留白 | 全场群众同步表演 |
| 一个物件突然不对劲 | 调查热点、覆盖图、音效、局部特写 | 背景物件自动产生复杂动画 |
| 大规模传说、历史、异地事件 | 全屏插画、分层视差、字幕、说书 | 在当前场景实时搭出所有人物 |
| 角色在空间中行动 | 世界场景走位、转向、出入场 | 任意复杂肢体接触 |
| 民俗动作和生死压力 | 专属小游戏、长按、节奏操作 | 通用按键雨 |
| 看不见的异常 | 声音、气味、三把火、滤镜、镜头停顿 | 必须把鬼完整画出来 |
| 物品、任务和后果 | 热点、条件、状态变化、后续对话 | 只在说明文字中宣告 |

## 四、关卡脚本的强制编写单位

以后每个可玩节拍至少写清以下七项：

1. **玩家目标**：玩家此刻想完成什么。
2. **进入条件**：从哪里来，什么状态下触发。
3. **玩家操作**：移动、调查、选择、长按、逃跑或其他动作。
4. **画面载体**：世界场景、图对话、过场插画、覆盖图或小游戏。
5. **声音载体**：环境声、关键音效、配音、静音或音乐变化。
6. **结果与状态**：任务、道具、金钱、人物态度、后续可见变化。
7. **表现级别**：A 档直接实现、B 档新增资产、C 档需要改写或单独立项。

推荐使用以下格式：

| 节拍 | 玩家操作 | 画面与声音 | 结果 | 表现级别／资产 |
|---|---|---|---|---|
| 示例：小二逼近 | 玩家仍可嘴硬选择一句 | 小二走近；茶馆人声减弱；椅脚拖地声从两侧响起 | 进入被轰出阶段 | A：NPC 走位、对话、音效 |

不能只写“播放一段演出”。必须写清演出由什么实际载体完成。

## 五、世界场景内表演的尺度

### 1. 一拍只抓一个主要动作

世界角色尺寸有限，同一拍塞入太多小动作，玩家既看不清，也会成倍增加动画资产。

不推荐：

> 关二狗攥紧饼、挺起胸、转头看众人、用手指比划墨斗线、吞口水、再缩肩退后。

推荐：

> 关二狗往前顶半步，梗着脖子把话说完。其余情绪交给立绘、台词和停顿。

### 2. 肢体接触必须单独标记

“推、拉、抱、扛、踢、咬、抢、扭打”都不是普通走位。每次出现都要判断：

- 是否已有对应动画。
- 能否用角色位移、音效和白闪代替接触本身。
- 是否值得为这一拍新增专属动作。

### 3. 背景人物默认不能响应

画在场景底图里的茶客、街坊和摊贩默认只是环境，不可直接命令他们转头、让路或逃跑。

需要群众反应时，优先按以下顺序处理：

1. 改变环境人声。
2. 播放椅脚、碗碟、窃语等离屏音效。
3. 让一到两个独立 NPC 走位或转向。
4. 必要时制作局部覆盖动画。
5. 只有真正关键的群戏才制作整套新场景版本。

### 4. 小表情交给对话立绘

“眼神闪烁、嘴角抽动、强笑、嫌弃、犹豫、心虚”等细节，应主要通过对话立绘、台词节奏和气泡表现，不依赖世界角色面部。

## 六、镜头和过场的正确用法

现有镜头可以：

- 在二维场景中平移。
- 缩放远近。
- 淡入淡出、黑屏、白闪。
- 加电影黑边、标题和字幕。
- 显示静态插画并进行缓慢推拉。
- 播放多层视差插画和少量循环动画层。
- 在过场中生成、移除、移动和转向少量角色。
- 叠加覆盖图并做透明度或图像间渐变混合。
- 在世界场景中保留深度遮挡、环境色、AO和角色投影阴影。

现有镜头不能：

- 改变成正面、低角度、仰视等全新摄影角度。
- 像 3D 摄像机一样环绕角色。
- 自动把世界角色切成手、眼睛、嘴角等真实近景。

这里的“不能”指当前内容工具和正式运行时没有现成原语，不代表 PixiJS 理论能力不足。需要上述效果时，必须先做新的表现能力或新美术镜头，不能靠剧本文字直接获得。

需要手部、面部或物件极近特写时，必须将它视为一张新增插画或覆盖图，而不是一句免费的镜头指令。

全屏插画应留给：

- 世界场景无法清楚表现的关键一瞬。
- 说书、传说、回忆、梦境和历史真相。
- 对主线有记忆价值的恐怖揭示。

日常对话和普通走路不要频繁切全屏插画，否则制作量失控，也会削弱关键镜头的分量。

## 七、声音是正式表现层，不是补丁

本作的恐怖和群体反应可以大量依靠声音完成。脚本细化时应主动写声音，而不是等制作阶段补。

优先使用：

- 环境人声突然减弱或消失。
- 椅脚拖地、碗底磕桌、门轴、布料、脚步、呼吸和远处叫喊。
- 声源从远到近、从单一方向变成多方向。
- 一段声音停下后留下不正常的空白。
- 画外声音与画面不一致。
- 重复声音逐次发生轻微变化。

声音可以替代一部分昂贵动画，但不能替代玩家必须看懂的关键因果。关键物件改变、人物进出和任务结果仍需有可见反馈。

## 八、对新增两份细化稿的具体校准

### 1. 茶馆掐架

可以直接保留：

- 关二狗蹭听、抬杠、说漏背尸身份。
- 玩家通过对话选择把牛越吹越大。
- 小二靠近，关二狗从横变怂。
- 被赶到门口后嘴硬放话。
- “规矩本”或见闻提示。

需要改写表现方式：

- “所有听客齐刷刷挪开”改为：茶馆人声突然低下去，两侧传来椅脚拖地声，一名可动茶客起身换位。
- “有人捂鼻、有人端碗躲开”不逐个演出；改由一两句窃语、嫌弃立绘或气泡代表。
- “小二搡肩”若无专属动作，可改成小二逼近、角色位置重叠前白闪一下，配衣料摩擦声，关二狗后退半步。
- “攥饼、挺胸、空中比划、抓扁担”等动作只保留一个最能立人物的主动作，其余交给台词。

### 2. 雾津街头半开放

可以直接保留：

- 摸橘子、捡铜板、算命、吹牛、接任务等热点与图对话结构。
- 成功或失败后改变钱、物品、受伤、价格和 NPC 态度。
- 以后路过听见报复性台词，表现“这户人家记仇”。
- 杠房作为背尸主线触发点。

需要新增资产或替代表现：

- 偷鸡：需要鸡的角色与扑腾动作；否则用篱笆热点、鸡叫、白闪和结果图标抽象表现。
- 踢猫狗：需要动物和反应动画；没有资产时不能写成实时场景动作。
- 袍哥路过：需要袍哥角色、行走队列和关二狗退避动作；属于 B 档事件。
- 壮汉蹲坑：需要专属人物画面或遮挡合理的局部场景，不能只靠普通站立 NPC 表现。
- 砸玻璃：若要求看见玻璃破碎，需要破前／破后状态图与碎裂音效；否则只能做画外事件。
- 正街、背街、城墙根：若三地要有显著美术和路线差异，需要多张背景或独立场景；若只使用现有“雾津街头”，应改成同一张地图里的几个功能区域，不夸大空间差异。

## 九、细化阶段的资产纪律

每份关卡脚本结尾必须附“新增资产清单”，分为：

- **场景**：新背景、昼夜版、破坏版、局部覆盖图。
- **角色**：新 NPC、动物、群众代表。
- **动画**：角色名、动作名、是否循环、触发位置。
- **插画**：全屏镜头、物件特写、梦境或回忆画面。
- **声音**：环境声、关键音效、配音和特殊静音节点。
- **UI／玩法**：新小游戏、新提示形态或特殊操作。

资产清单不能只写“若干动画”“若干音效”。必须能反查到具体节拍。

同一动作只服务一个不重要笑点时，应优先找低成本替代；同一动作会在主线、支线和开放区重复使用时，才更值得制作。

## 十、关卡脚本交稿前检查表

- [ ] 每一拍都写明玩家实际做什么。
- [ ] 每一拍都能指出画面和声音由什么载体承担。
- [ ] 没有默认背景群众可以自由表演。
- [ ] 没有把世界角色的小脸当作电影特写使用。
- [ ] 每次推、拉、踢、咬、抢、扭打都标记了动画或替代方案。
- [ ] 每个新动物、新 NPC、新物件状态都有资产声明。
- [ ] 镜头只使用二维平移、缩放、淡变、插画和视差能力。
- [ ] 复杂历史或传说优先考虑插画过场，而不是强塞进世界场景。
- [ ] 群体反应优先使用声音、空间和少数代表 NPC。
- [ ] 关键因果既有声音反馈，也有玩家能确认的可见结果。
- [ ] 新场景、新小游戏和新表现原语没有被悄悄当成现成能力。
- [ ] 资产被削减时，核心剧情信息仍能成立。

## 十一、最终原则

关卡细化不是把故事写得越像电影越好，而是把骨架转化成玩家能够 **走到、看到、听到、按下、选择并承担后果** 的过程。

本作最有力的表现手段不是大规模动画，而是：

- 一张不对劲的手绘场景。
- 一个能被玩家亲手触发的民俗动作。
- 一两名关键人物的站位变化。
- 一段忽然消失的人声。
- 一句在错误距离响起的话。
- 一个过后才显出后果的选择。
